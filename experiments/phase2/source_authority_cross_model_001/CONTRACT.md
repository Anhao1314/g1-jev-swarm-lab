# Phase 2.4.2 frozen comparison contract

This is an additive development/regression Pilot using the 528 previously observed sources and unchanged historical DeepSeek B candidates. DD is the completed v2 DeepSeek issuance evidence; DG changes the issuer to GLM-5.3-Flash with its already approved preflight configuration. No compiler, DD or bounded-control provider calls are repeated.

The same full source, candidate-blind v2 prompt/parser, deterministic host comparison, release gate, Guard, IR validator and scoring rules are retained. The issuer sees only `{"source": ...}`. No labels, case IDs or B-derived information enter provider requests. No source-language coverage restriction is added.

Keep GLM thinking enabled and reasoning effort omitted. Keep 4096 output tokens, temperature zero, timeout 60 seconds and two transport retries with 0.5-second backoff. JSON-object mode and Chat transport match the verified GLM integration. These unavoidable provider differences and longitudinal acquisition must be disclosed; the Pilot cannot identify model-only causal effects.

An independently correct specific typed rejection is semantic gain, including a usable UNKNOWN with a correct missing-unit issue. Generic UNKNOWN, backend/schema failure, reasoning/output exhaustion and host plan disagreement receive no semantic rejection credit. Raw reasoning is never a certificate and is not persisted. Audit every known unsafe case and every extra valid loss against unchanged full source and labels; keep disputed Sensitivity separate from Primary.

Existing v2 operational gates are retained without retuning. D011 stays candidate; Runtime stays blocked. No fresh held-out source is created or evaluated. The only decision is whether observed development evidence justifies a later independent held-out evaluation.

Each stage stores only its first semantic response, immutable request hash, sanitized wire response and attempt ledger. Resume replays durable first output or records interrupted unavailability without reissuing. Credentials and credential hashes are never stored. Old tracked files are checked as exact raw bytes against the starting snapshot.
